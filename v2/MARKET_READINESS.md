# بوابة الجاهزية السوقية — شموس V2

لا يُصنّف الإصدار «جاهزًا للعرض في السوق» إلا عند نجاح جميع البنود الإلزامية أدناه بنتيجة آلية أو دليل مراجعة محفوظ.

## P0 — مانع للإطلاق

- [x] لا تحفظ V2 كلمات مرور أو أسرار مصادقة داخل ملفات الواجهة.
- [x] مصادقة V2 خادمية مستقلة: scrypt، TOTP، رموز استعادة أحادية الاستخدام، جلسات 30 دقيقة قابلة للإلغاء، وقفل محاولات الدخول.
  - [ ] تفعيل `V2_STRICT_AUTH=true` و`V2_AUTH_KEY` ثابت في بيئة العرض/الإنتاج وإتمام تهيئة الحسابات المخولة.
- [x] عزل V2 ماديًا ومنطقيًا عن تخزين V1.
- [x] عدم إمكانية حذف أو إعادة كتابة قيد مرحّل.
- [x] التعديل المالي يتم بالعكس ثم القيد التصحيحي.
- [x] منع الترحيل في الفترات المقفلة.
- [x] منع الكتابة فوق إصدار أحدث من البيانات.
- [x] معاملات ذرية تربط مستندات المبيعات والمشتريات والتحصيل والسداد والرواتب بقيودها وذممها؛ ربط المخزون التفصيلي ما زال ضمن P1.
- [x] مصفوفة صلاحيات مركزية وصريحة لكل أمر، مع فصل الإنشاء والاعتماد والإلغاء والإقفال وإعادة الفتح.
- [ ] نسخ احتياطي مشفر واختبار استعادة فعلي موثق بزمني RPO وRTO.
  - [x] تشفير AES-256-GCM، تحقق SHA-256، وصلاحية مقيدة لفحص الاستعادة غير المتلف.
  - [ ] تنفيذ استعادة كاملة في بيئة مرحلية وقياس RPO/RTO واعتمادهما تشغيليًا.
- [x] صفر اختبارات فاشلة في حزمة V2 الحالية.
- [ ] صفر ثغرات حرجة أو عالية غير مقبولة في تبعيات الإنتاج.
- [ ] اختبار اختراق للملكية الأفقية IDOR، وCSRF، وXSS، ورفع الملفات، وإدارة الجلسة.

## P1 — اكتمال المنتج

- [ ] CRM: عميل، منشآت، جهات اتصال، فرص، عروض، تحويل إلى عقد، وسجل تواصل.
  - [x] سجل عميل موحد، فرص، عروض سعر، اعتماد بفصل المنشئ عن المعتمد، وتحويل العرض المعتمد إلى عقد.
  - [ ] جهات الاتصال المتعددة، سجل التواصل متعدد القنوات، الاستيراد الجماعي، والتنبؤ المتقدم بخط المبيعات.
- [ ] العقود: إنشاء، تعديل، اعتماد، تفعيل، تجديد، إلغاء، SLA، فهرسة، وربحية.
  - [x] إنشاء العقد من عرض معتمد، التفعيل، التجديد مع منع التكرار، وربط تقارير الربحية المالية.
  - [ ] تعديلات العقود المؤرخة، الإلغاء التشغيلي، فهرسة المستندات، وتسعير SLA متعدد المستويات.
- [ ] الميدان: بلاغ، أمر عمل، توزيع، مسار، تنفيذ، قطع، صور، توقيع، اعتماد وإغلاق.
  - [x] بلاغ بمهلة SLA، إسناد إلى فني، أمر عمل، توقيع إلزامي، معالجة وإغلاق موثق.
  - [ ] تحسين المسارات، العمل دون اتصال، الصور وقوائم الفحص التفصيلية واعتماد المشرف.
- [ ] الأصول: دورة حياة، مكونات، فحص، مخالفات، تاريخ أعطال، MTBF وMTTR.
  - [x] ربط أعطال الأصول بأوامر العمل وحساب MTBF وMTTR من الأحداث المكتملة.
  - [ ] سجل المكونات والتغيير، الفحوص والمخالفات، الصيانة التنبؤية وIoT.
- [ ] المخزون: مستودعات، سيارات، حجز، تحويل، جرد، دفعات/أرقام تسلسلية وتقييم.
  - [x] استلام موزون التكلفة، حركة صرف، منع الرصيد السالب، وقيد تكلفة العقد.
  - [ ] الحجز والتحويل والجرد والدفعات/الأرقام التسلسلية وسياسات التقييم المتعددة.
- [ ] المشتريات: RFQ، عروض موردين، أمر شراء، اعتماد، استلام، فاتورة ومطابقة ثلاثية.
  - [x] اعتماد منفصل، استلام، فاتورة مخزون، ومطابقة أمر/استلام/فاتورة.
  - [ ] RFQ ومقارنة عروض الموردين والمرتجعات وفروق السعر والكمية.
- [ ] المالية: مبيعات، مشتريات، قبض، صرف، بنوك، تسوية، ذمم، ضرائب اختيارية، إقفال وتقارير.
  - [x] مبيعات ومشتريات وقبض وسداد وبنوك وتسوية وذمم وضريبة اختيارية وإقفال وتقارير مصدرها القيود.
  - [ ] اعتمادات الصرف المتقدمة، ميزانيات، مراكز تكلفة متعددة المستويات، وتكامل بنكي مباشر.
- [ ] الموظفون: ملف، عقد عمل، راتب، سلفة، عهدة، مصروف، مسير، اعتماد ودفع.
  - [x] ملف أساسي، راتب، سلفة، مصروف بمرفق إلزامي، استحقاق المسير ودفعه، مع الإلغاء والتصحيح بالعكس.
  - [ ] عقد العمل، العهد التفصيلية، تسوية نهاية الخدمة، حماية الأجور وملفات البنك المعتمدة.
- [ ] بوابة عميل وتطبيق فني Offline مع حل تعارضات واضح.
- [ ] إشعارات وقوالب واتصالات وسجل تسليم وموافقة المستخدم.
  - [x] طابور إشعارات داخلي، موافقات حسب القناة، تسجيل نتيجة التسليم والمحاولات، وأثر تدقيق.
  - [ ] ربط مزودي البريد والرسائل النصية فعليًا، قوالب معتمدة، إعادة محاولة آلية ومراقبة معدل التسليم.
- [ ] PDF وCSV/XLSX وتقارير RTL قابلة لإعادة الإنتاج.
  - [x] تقارير مالية خادمية، CSV محمي من حقن الصيغ، وطباعة PDF من نفس نسخة التقرير.
  - [ ] تصدير XLSX أصلي وقوالب PDF معتمدة نهائيًا واختبارات إعادة الإنتاج البصرية.

## الامتثال للفوترة الإلكترونية

- [x] تحقق أولي لحقول الفاتورة والأرقام الضريبية والإجماليات وحمولة QR بتنسيق TLV.
- [ ] اجتياز كل فاتورة XML لأداة التحقق الرسمية ZATCA SDK؛ نجاح التحقق الأولي الداخلي لا يعني اعتماد الهيئة.
- [ ] التوقيع والختم التشفيري وسلسلة العداد/الهاش بشهادة جهاز فعلية.
- [ ] اختبار Clearance للفواتير القياسية وReporting للمبسطة في بيئة المحاكاة ثم الإنتاج.

## P2 — جودة العرض التجاري

- [ ] رحلة عرض تجريبي ببيانات اصطناعية لا تحتوي بيانات عملاء حقيقية.
- [ ] Empty/loading/error/offline states في جميع الصفحات.
- [ ] قابلية استخدام لوحة المفاتيح، قارئ الشاشة، التباين، والجوال.
- [ ] زمن تحميل أولي وأداء قوائم كبيرة ضمن ميزانية محددة.
- [ ] مراقبة الأخطاء والصحة والسجلات دون تسريب بيانات شخصية.
- [ ] سياسة خصوصية، شروط استخدام، احتفاظ بالبيانات، وتصدير/حذف وفق الصلاحية.
  - [x] تصدير JSON مدقق لصاحب العلاقة، وسياسة احتفاظ تنقّح البيانات التشغيلية المؤهلة ولا تحذف السجلات المالية.
  - [ ] اعتماد النصوص القانونية ومدد الاحتفاظ حسب نوع السجل، ومسار طلبات التصحيح/المحو المقيدة قانونيًا.
- [ ] دليل تشغيل، إعداد أولي، نسخة احتياطية، استعادة، وترقية.

## حالة الإصدار

الحالة الحالية: **غير معتمد سوقيًا**. وجود هذه المصفوفة يمنع إعلان الجاهزية اعتمادًا على الانطباع البصري فقط.
